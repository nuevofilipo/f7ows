2026-06-01 — Three-level retrieval intent (specific / inbetween / global), medoid removed
==========================================================================================
WHAT
- Retrieval is now intent-driven, not corpus-size-first:
    specific  -> pgvector top-k over content_full
    inbetween -> skeleton (LLM picks ltree branches) for ANY corpus size
    global    -> corpus<=budget ? stuff-all : skeleton
  Reason: "summarise topic X" needs all of ONE topic, not the whole project, so it
  must focus (skeleton) even on a small corpus instead of blindly stuffing.
- intent="auto": free keyword pass (specific vs not) -> only on a hit, one cheap LLM
  call (_llm_classify_scope) splits inbetween vs global (fallback: inbetween).
- Removed the medoid strategy entirely (lossy). Skeleton planner failure now falls
  back to a budget-capped _stuff. Clusters are still computed (map UI), just not
  used for retrieval.
- Removed `scope` plumbing everywhere (router/grounded_answer/send_message/prefs/
  REPL); dropped preferences.default_scope; default_intent choices now
  (auto, specific, inbetween, global).
- Slash commands no longer force intent=global. Instead each carries a
  retrieval_keyword ("mockexam"/"deepsummary") that is appended to the *routing*
  query (new grounded_answer routing_query arg) so they always trip the keyword
  pass and reach the classifier — answer still grounded on the real query, so no
  text pollution. deepsummary outline + sections inject the keyword too.
- planner_max_tokens (added earlier) also powers the new classifier call.
- retrieval.md trace drops scope, shows the classified intent + chosen strategy.

WHY
- The old flow stuffed the whole corpus for any global-ish query on a small project,
  wasting context and ignoring topic focus. Three levels give a clean mental model
  and reuse the existing skeleton machinery for the middle case.
